# Implementation Register · Rejestr implementacji

---

## English

An open public register of tools and systems implementing APS. Listing is free of charge
and non-exclusive. The register is **not** a product certification or a vendor
recommendation. The rules governing the register are in
[`GOVERNANCE.md`](GOVERNANCE.md); the rules for using the name are in
[`TRADEMARK.md`](TRADEMARK.md).

### How to submit an implementation

Open an issue with the `implementation` label — use the *Implementation register entry*
template — and state:

1. The name of the tool or system and the party responsible for it.
2. The version of APS it implements.
3. Which components of the standard are supported and which are not: the AI Registry,
   content classification (Category A / B / C), documentation of human creative
   contribution (chain of title), ToS snapshots, AI Disclosure, the delivery package.
4. How the artefact is produced: the output format and how reproducibility of the
   evidence is ensured.
5. The address of public documentation or of a demonstration, if one exists.
6. Its nature: open, commercial, internal.

Submissions are considered in public, in the thread of the submission.

### Rules

- An entry states only the declared and verifiable scope of component support.
- Incomplete scope is no obstacle to an entry; it is described, not concealed.
- The specification editor does not decide entries for tools connected with the editor
  (see [`GOVERNANCE.md`](GOVERNANCE.md), section 7).
- A reference implementation, if one is produced, is published under the licence of the
  standard and belongs to the standard, not to whoever built it.

## Polski

Otwarty, jawny rejestr narzędzi i systemów wdrażających APS. Wpis jest nieodpłatny
i niewyłączny. Rejestr **nie jest** certyfikacją produktu ani rekomendacją dostawcy.
Zasady prowadzenia rejestru opisuje [`GOVERNANCE.md`](GOVERNANCE.md), zasady posługiwania
się nazwą — [`TRADEMARK.md`](TRADEMARK.md).

### Jak zgłosić implementację

Otwórz zgłoszenie (issue) z etykietą `implementation` — szablon *Implementation register
entry* — i podaj:

1. Nazwę narzędzia lub systemu oraz podmiot odpowiedzialny.
2. Wersję APS, którą implementuje.
3. Które komponenty standardu są obsługiwane, a które nie: Rejestr AI, klasyfikacja
   treści (Kategoria A / B / C), dokumentacja ludzkiego wkładu twórczego (chain of
   title), snapshoty warunków usług (ToS), AI Disclosure, pakiet dostawy.
4. Sposób wytworzenia artefaktu: format wyjściowy i sposób zapewnienia odtwarzalności
   dowodu.
5. Adres publicznej dokumentacji lub demonstracji, jeżeli istnieje.
6. Charakter: otwarty, komercyjny, wewnętrzny.

Zgłoszenia rozpatrywane są jawnie, w wątku zgłoszenia.

### Zasady

- Wpis stwierdza wyłącznie zadeklarowany i sprawdzalny zakres wsparcia komponentów.
- Zakres niepełny nie jest przeszkodą do wpisu; jest opisywany, nie ukrywany.
- Redaktor specyfikacji nie rozstrzyga o wpisach narzędzi z nim powiązanych (zob.
  [`GOVERNANCE.md`](GOVERNANCE.md), sekcja 7).
- Implementacja referencyjna, jeśli powstanie, publikowana jest na licencji standardu
  i należy do standardu, nie do jej wykonawcy.
